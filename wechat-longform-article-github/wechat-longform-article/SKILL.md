# 微信公众号超长图文创作（竹心一言）

把"多平台调研 → 长文写作 → HTML排版 → 配图 → 自检交付"做成一条可复用流水线。最终产物是**一个可直接发布的 `.html` 文件**。

## 硬性约束（每条都必须满足，交付前逐条核对）

1. **字数**：正文（不含HTML标签）中文≥20000字、≤45000字；用户未指定时目标25000–35000字。必须用 `scripts/word_count.py` 实测，禁止估算。
2. **平台数**：素材来源≥10个平台，且至少含1个视频平台。平台清单与采集法见 [references/platforms.md](references/platforms.md)。
3. **日期范围**：严格限定在用户给定的起止日期内；用户写"XXX-XXX"等占位符时，先追问具体起止日期再开工。
4. **配图与视觉组件**：全文≥10张图片，每800–1800字一张，置于段落间并配图注。封面、章节头图、场景插画、概念图、氛围图等类型交替使用，避免连续两张同类型图。同时必须使用模板提供的视觉组件打破长文节奏——全文至少用到**6类**不同组件（从章节卡片、渐变标题、彩色标签段落、金句卡片、对话气泡、人物卡片、Q&A问答、红绿对比、数据卡片、单数据大卡、时间线、双列对比、数字步骤、要点列表、关键词标签云、旁注中选取），不要全文都是纯段落。每连续3段纯文字后必须插入配图或组件。来源规则见下文"配图与视觉组件"。
5. **正文色彩密度（防黑字疲劳）**：禁止出现整段纯黑字。每个正文段落（17px正文区）至少包含一处内联色彩变化，从以下6种手法中选用：①主题色加粗标关键词；②多色荧光笔高亮（黄=核心观点/粉=反常识/蓝=数据/绿=积极/橙=转折，五色按语义轮换，不要只用一种）；③关键数字彩色大号强调（红=下降/警示、绿=增长、主题色=重要）；④段首2–4字彩色引导词（"先说结论。""问题在于。"等）；⑤核心判断句整句主题色加粗放大单独成段；⑥情绪/判断词着色（红=愤怒、橙=无奈、蓝=冷静）。目标是让读者每隔一两行就能看到一个"颜色落点"，而不是密密麻麻一屏黑字。具体写法见模板组件5和 writing-guide.md 第七节。
6. **作者**：文末署名"竹心一言"。全文第一人称"我"。
7. **零AI作者身份**：全文（含图注、文末）不得出现任何表明"本文由AI/大模型/机器生成或撰写"的身份声明（如"本文由AI生成""作为AI助手""我是一个语言模型"），也不得出现AI拒答话术（"我无法访问互联网"等）。**注意：AI、人工智能、大模型、ChatGPT等词作为文章讨论对象时完全可以正常使用**，科技类主题无需回避；真正要避免的是"AI腔"——模板化元话语、通稿感、缺乏个人体温。用 `scripts/scan_ai_traces.py` 扫描身份声明（硬门槛），元话语只作提示，由模型结合语境自行判断是否改写。
8. **微信兼容**：所有样式必须内联（`style="..."`），不得用 `<style>` 标签/class/id/JS/外链CSS/表单/`position`/浮动；图片用 `<img>` 且设 `width="100%"`。只用 [assets/template.html](assets/template.html) 里已有的组件，不自行发明样式。渐变用 `background-color` 纯色兜底 + `background-image:linear-gradient(...)` 渐进增强。组件用法与配色选择见 [references/writing-guide.md](references/writing-guide.md)。
9. **可直接发布**：产物为单文件HTML，本地浏览器打开排版正常，复制全文粘贴到公众号后台后样式与图片不丢失（图片URL须为公网可访问地址）。

## 工作流

### 第0步：确认参数
从用户指令中解析：**主题、起止日期、目标字数（默认2.5–3.5万）、平台数（默认≥10）、风格倾向（深度调查/观点评论/故事叙事/科普干货）、配色主题（默认bamboo竹青，按 writing-guide.md 第八节根据主题自动匹配）、是否有指定立场或角度**。任一关键参数缺失（尤其日期、主题）先追问，不要带着占位符开工。

### 第1步：多平台调研（≥10平台）
按 [references/platforms.md](references/platforms.md) 执行。要点：
- 并行调用 `general_search` 覆盖图文/新闻/问答类平台；视频平台（抖音/B站/快手）的内容用 `doubao-video-extract` skill 提取字幕、逐字稿、评论要点。
- 需要登录态或反爬严格的平台（小红书、微博、抖音等）用 `browser-task` skill 兜底采集可见内容。
- 每个平台至少产出：核心事实/数据、代表性观点、具体案例或人物、金句或原话、来源URL与发布时间。
- 素材去重、交叉验证；矛盾信息标注多版本说法，写作时呈现争议而非只取一端。
- 把整理后的素材写入工作目录的 `research_notes.md`（临时文件，不交付）。

### 第2步：搭大纲
2–4.5万字长文建议8–15个一级章节，每章2000–4000字，章下设2–4个小节。结构遵循：
**钩子开篇 → 背景与来龙去脉 → 多维度展开（现象/人物/利益/争议/数据）→ 深度归因 → 案例与故事 → 观点碰撞 → 落点与升华**。
在大纲中标注每章计划字数、配图位置和拟用的视觉组件。写作风格、节奏、去AI味的具体手法见 [references/writing-guide.md](references/writing-guide.md)。

### 第3步：配图与视觉组件
- **优先AI生成**：封面、章节头图、场景插画、概念图、氛围图用 `image_gen`（按需先 `tool_search` 加载）。**配图prompt必须强调色彩丰富、画面饱满、有视觉冲击力**——明确要求"色彩鲜艳明快、高饱和度、光影层次丰富、插画/摄影风格有质感"，避免灰暗、单调、素色的配图；不同章节的配图在色调和构图上要有变化，让读者翻到每一章都有新鲜感。prompt 中不得要求生成文字（微信图内文字易糊）；生成后取公网URL直接写入HTML。
- **配图类型交替**：封面图（16:9/2.35:1）→ 场景插画 → 概念氛围图 → 信息图/数据图 → 人物/故事场景图，交替使用，不要连续多张同风格。每章至少1张图，重磅章节2–3张。
- **网络搜图仅用于必须真实的实体**（人物、产品、地点、新闻现场），用 `image_search`；其URL可能有防盗链，须在交付说明中提示用户"发布前在公众号后台重新上传该图"。搜来的图在图注中标注来源。
- **能用HTML组件实现的就不依赖图片**：时间线、数据对比、定义解析、要点清单、流程步骤、正反对比直接用模板组件（纵向时间线、三列多彩数据卡、单数据大卡、双列对比卡、数字步骤卡、五色标签段落、关键词标签云），既清晰又不占图片额度。**但复杂的信息图、概念关系图、发展历程图等，用 `image_gen` 生成色彩丰富的信息图**（类似彩色时间线、多节点关系图、数据可视化图），这类图本身就是大块色彩，能极大缓解长文疲劳，全文至少安排1–2张。
- 图片比例：封面16:9或2.35:1，正文配图4:3或16:9；所有 `<img>` 加 `style="width:100%;display:block;border-radius:10px;"`。
- **两种图注样式交替使用**：标准小字灰色图注（`margin:8px 0 0`）和色条图注（图片圆角在上、图注在主题色色条上白字，杂志感更强），让排版有节奏变化。
- 每张图配一句图注，图注本身也算正文内容，不能写"AI生成"。

### 第4步：分章写作
- 以 `assets/template.html` 为骨架，按大纲逐章填充。一次写一章，写完用 `scripts/word_count.py` 累计字数，动态调整后续章节篇幅。
- 第一人称、有体温、有判断；多用具体人名、地名、时间、数字、直接引语，少用形容词和排比堆砌。
- **边写边上色**：不要写完再统一加样式。每写一段就顺手在段内加入至少一处内联色彩——关键词用主题色加粗、核心观点用黄色荧光笔、关键数字用彩色大号字、段首加彩色引导词、核心判断单独成段用主题色放大。荧光笔五色按语义轮换，不要一段里全是同一种颜色。
- 事实与数据自然融入叙述，不在正文贴URL；如需列参考来源，统一放文末"参考资料"小节，以平台+标题的纯文字形式列出（不放链接，避免微信清洗）。
- 严禁词与改写规则见 [references/writing-guide.md](references/writing-guide.md)。

### 第5步：HTML排版
- 复制 `assets/template.html`，替换标题、作者、正文各节。
- 使用模板内已有的内联样式组件（共22类）：标题区（装饰色条+导语）、章节卡片标题（浅底+左色条+可选胶囊）、渐变章节标题（深色底白字，重磅章节用）、小节标题、正文段落（6种内联色彩手法：主题色加粗/多色荧光笔/数字强调/段首引导词/核心句强调/情绪词着色）、彩色标签段落（五色可选，标签词根据内容自定义2–4字，如"背景""转折""风险""冷知识"，不要死用"定义/解析/影响"）、金句卡片、对话气泡、人物卡片、Q&A问答块、红绿对比行、浅色旁注、三列多彩数据卡片、单数据大卡（深色渐变底）、纵向时间线、双列对比卡、数字步骤卡、要点列表、关键词标签云、配图（标准/色条图注两种）、分隔符（三色圆点/短线两种）、参考资料、作者署名区。组件用途与频率见 [references/writing-guide.md](references/writing-guide.md) 第七节。
- 不新增JS、不写`<style>`、不用class/id/position/浮动；如需新组件，继续用内联style并同步更新模板。
- **纸质背景**：正文容器固定为暖米色 `#faf7f0`（不随主题变），正文用柔灰 `#3a3a3a` 而非纯黑，降低对比度，长读不刺眼；组件卡片用纯白 `#ffffff` 浮在暖米底上形成层次。不要把正文容器背景改成纯白或其他颜色。
- 移动端字号17px、行高1.9、段间距20px；图片间距收紧为18px，保持视觉密度。主题色克制（一个主色+灰阶+五个功能标签色），但正文内要大胆用多色荧光笔、彩色数字、彩色引导词让文字"有疏有密、有黑有彩"，再配合多彩数据卡、标签云、渐变标题等组件让版面"花"起来。
- **换色**：定稿后根据主题选配色（科技蓝/暖橙/墨黑等10套，见 writing-guide.md 第八节），运行 `python3 scripts/apply_theme.py article.html <主题名>` 一键替换，不要手动改颜色。默认竹青，拿不准主题就不换。

### 第6步：自检（全部通过才能交付）
在工作目录依次运行：
```bash
python3 <skill_dir>/scripts/word_count.py article.html
python3 <skill_dir>/scripts/scan_ai_traces.py article.html
```
- 字数不达标→扩写薄弱章节；超标→精简重复论证。
- 身份声明命中→必须删除；元话语提示项→结合语境自行判断是否改写（AI主题词正常使用不算问题）。
- 若需要换主题色，先运行 `python3 <skill_dir>/scripts/apply_theme.py article.html <主题>`，换色后重新跑一次AI扫描确认无误。
- 人工再过一遍：图片是否都能加载、图注是否齐全、署名是否为"竹心一言"、是否有残留占位符/TODO/示例文字、日期是否在范围内、平台是否≥10、配图是否≥10张且每800–1800字一张、视觉组件是否至少用到6类、全文是否有连续3段以上纯文字无配图无组件（有则打破节奏）、配图色彩是否饱满不灰暗、两种图注样式是否有交替、**正文是否有整段纯黑字无任何色彩变化（有则补荧光笔/彩色加粗/数字强调）、荧光笔颜色是否有轮换而非一黄到底、正文容器背景是否为暖米色#faf7f0而非纯白、彩色标签词是否根据内容自定义而非千篇一律"定义解析影响"**。

### 第7步：交付
- 用 `present_files` 交付最终 `.html`（文件名用文章主题或标题命名，英文/拼音均可）。
- 附简短说明：实际字数、配图数量、覆盖平台数、所用配色主题；若含网络搜图，提醒发布前在公众号后台重新上传那些图。
- 不交付 `research_notes.md` 等中间文件。

## 关键提醒
- 这是"竹心一言"本人的原创文章，不是报告、不是综述、不是资料汇编。要有作者的立场、观察和情绪。
- 长文的节奏靠"故事—分析—故事"交替维持，避免连续3段以上纯议论。
- **视觉密度是可读性的生命线**：2万多字的纯文字墙会劝退读者。宁可多插一张图、多用一个组件，也不要让屏幕上连续三屏都是白底黑字。配图要色彩鲜艳，组件要多彩交替，让读者每隔几百字就遇到一个视觉停顿。
- **正文本身要有色彩节奏**：黑字是底色，不是全部。每段都要有彩色关键词、荧光笔或彩色数字，让读者的视线在段落中能"抓住"几个彩色落点。但色彩要为语义服务——黄色标观点、蓝色标数据、红色标警示，不要为上色而上色，更不要把整段都染成彩色。
- 遇到平台采不到内容，换平台或换关键词，不要编造数据和引语；宁可少一个案例，不可造一个事实。
