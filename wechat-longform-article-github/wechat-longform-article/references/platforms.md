# 多平台调研清单（≥10平台，含视频）

调研目标不是"每个平台都搜到"，而是让素材在**立场、形态、信源类型**上形成交叉：官方通报、当事人自述、媒体深度、网友评论、视频现场、数据报告，至少覆盖四类。

## 采集方法

1. **先并行后精读**：先用 `general_search` 一次并行3个query覆盖不同平台和角度，拿到摘要后挑高价值URL用 `web.fetch` 精读全文。
2. **query设计**：
   - 事实类："关键词 日期/月份 发生了什么"
   - 观点类："关键词 如何评价/怎么看 site:zhihu.com"
   - 现场类："关键词 视频/现场/实拍"（配合视频平台）
   - 数据类："关键词 数据/报告/统计 2026"
   - 时间约束：在query里带上日期范围或月份，过滤旧闻。
3. **视频内容必走 `doubao-video-extract`**：拿到字幕和逐字稿后，提取当事人原话、关键时间点、评论区高频观点。不要只看视频标题就写。
4. **登录态平台走 `browser-task`**：小红书、微博正文、抖音网页版等搜不到或要登录时，用浏览器技能真实操作，采集可见的标题、正文、点赞评论数、热评。
5. **每条素材记录五要素**：`平台 | 发布时间 | 核心事实/观点 | 原文金句或数据 | URL`，汇总进 `research_notes.md`。
6. **时间范围过滤**：只采用用户指定起止日期内发布/发生的内容；早于起点的背景材料可用于"历史层"，但要注明时间。
7. **交叉验证**：关键事实至少两个独立来源印证；只有单一来源的，写作时标注"据某某平台消息"并降低断言强度。
8. **平台数自检**：交付前数 `research_notes.md` 里出现了多少个不同平台域名/名称，不足10个或没有视频平台，回去补采。

```markdown

## 平台覆盖清单
- [ ] 抖音  [ ] B站  [ ] 微博  [ ] 知乎  [ ] 小红书 ...（≥10，含视频）

## 时间线
- 日期：事件 / 来源平台 / URL

## 关键事实与数据
- 事实（来源，日期，URL）

## 人物与案例
- 人物：身份、经历、原话、来源

## 观点光谱
- 正方：观点 / 代表发言 / 来源
- 反方：……
- 中间/其他：……

## 金句库
- "原话" —— 谁说的，来源

## 争议点与待核查
- 说法A vs 说法B
```
