# 写作指南：风格、结构与去AI味

本文件是写作阶段的详细参考。目标是让2–4.5万字读起来像"竹心一言"本人花了一周时间、带着个人判断写出来的原创深度文，而不是资料汇编或通稿。

## 一、文章结构

### 开篇（800–1500字）
用一个具体场景、一个人物、一个反差强烈的事实或一段对话切入，不要用"随着……的发展""近年来"开头。三段之内让读者知道这件事和他有关、值得花很长时间读下去。开篇结尾处自然亮出全文要回答的核心问题。

### 主体（按内容选2–4种推进方式交替使用）
- **现象层**：发生了什么，当事人怎么说，舆论场什么反应。
- **人物层**：把抽象议题落到具体的人——他的一天、他的选择、他的代价。
- **利益层**：谁在赚钱、谁在承担成本、链条怎么转、钱从哪来到哪去。
- **争议层**：把对立观点都摆出来，让双方用自己的话吵架，作者暂不站队或晚一点站队。
- **数据层**：用3–5个关键数字锚定规模和趋势，数字要带来源（平台名+机构名），但不贴链接。
- **历史层**：往前倒三年五年，这件事是怎么一步步走到今天的。
- **比较层**：和别的地区、别的行业、别的年代比。

### 结尾（800–1500字）
回到开篇的人物或场景，给出作者的判断或态度，但不要喊口号、不要升华到空洞的"时代""我们都"。可以留一个开放问题。最后是署名"竹心一言"。

### 章节配比参考（以3万字为例）
- 开篇 1500
- 背景来龙去脉 3000
- 现象与人物 6000（2–3章）
- 利益链/深度归因 6000（2章）
- 争议与多视角 4500（1–2章）
- 案例与故事 4500（1–2章）
- 趋势判断与落点 3000
- 结尾 1500

## 二、语言风格

1. **第一人称"我"在场**：写"我注意到""我翻了几百条评论后发现""我和一位从业者聊了很久"，而不是"据统计""有分析认为"。
2. **句子长短交替**：长句讲逻辑，短句砸重点。每出现一个三行以上的长句，后面跟一个短句。
3. **具体碾压抽象**：不说"价格很高"，说"一份卖到38块，比去年贵了11块"；不说"很多人"，说"评论区里点赞最高的三条都在骂"。
4. **直接引语制造现场感**：每章至少1–2处带引号的原话，可以来自采访、视频字幕、评论区、公开表态。引语要像人说的话，不要书面化。
5. **有判断、有偏好、有情绪**：作者可以愤怒、可以惋惜、可以保留态度，但不要端着。避免"客观中立"到没有观点。
6. **段落短**：手机阅读一段不超过4行，超过就拆。
7. **少用成语和排比**："不仅……更……""一方面……另一方面……""值得一提的是"这类句式能删就删。
8. **口语连接词**：用"说白了""问题在于""有意思的是""可你猜怎么着"代替"此外""然而""综上所述"。

## 三、避免AI腔：什么能写、什么不能写

核心原则：**读者读完不能觉得"这是AI写的"，但文章完全可以正常讨论AI。** 不要把"AI""大模型""ChatGPT"当敏感词——主题就是科技、AI、互联网时，这些词该用就用，用得准确、用得在行，反而像真人写的。

### 硬禁止：声明"本文由AI写的"（出现即不合格）
只有这类表述绝对不能有，因为它们直接告诉读者作者不是人：
- "本文由AI生成/撰写/创作""这是AI生成的内容""内容由大模型生成"
- "作为一个AI/语言模型/智能助手""我是一个AI助手""本助手"
- AI拒答话术："我无法访问互联网""我不能预测""我没有实时数据"
- 客服式结尾："如果您还有其他问题欢迎随时提问"
- 任何"声明：本文由AI生成"类标注

### 完全允许：AI相关词汇作为讨论对象
"AI、人工智能、大模型、语言模型、ChatGPT、GPT、Claude、Gemini、文心一言、通义千问、豆包、DeepSeek、AIGC、prompt、机器学习、神经网络、算法、训练、推理"等，只要是在**讨论事物本身**而不是**描述作者身份**，正常使用即可。写AI发展史就大大方方写"1956年人工智能一词诞生"，写行业分析就直接点名各家大模型。

### 风格警告：让文章像通稿的元话语（结合语境自行判断）
这些不是硬禁忌，人类偶尔也会写，但密集出现就是AI腔。用 `scan_ai_traces.py` 扫出后逐条判断：自然的留着，套话改成第一人称。

| 套话 | 改法 |
|---|---|
| 根据搜索结果 / 综合各平台信息 | 我翻遍了能找到的资料 / 我在几个平台来回刷了三天 |
| 数据显示 / 研究表明 | 我查到的一组数字是 / 某某机构在报告里写 |
| 有观点认为 / 有人指出 | 评论区一个高赞回答说 / 一位从业者告诉我 |
| 综上所述 / 总而言之 | 说白了 / 兜兜转转一句话 |
| 让我们一起来看看 | 我先从……说起 |
| 随着……的快速发展 | 直接写具体变化："这两年，……" |
| 在当今社会 / 众所周知 | 删掉，直接说事 |
| 本文将从以下几个方面 | 删掉，用故事开场 |
| 值得一提的是 / 不可否认 | 删掉，直接写那件事 |
| 首先/其次/最后（机械罗列） | 用小标题和过渡句代替 |
| 赋能 / 抓手 / 闭环 / 底层逻辑 | 换成正常人说的话 |
| 据悉 / 据了解 | "我查到""我听说" |
| 引发了广泛关注 / 引起热烈反响 | 写具体多少阅读、什么反应 |
| 感谢您的阅读 / 仅供参考 / 欢迎点赞关注 | 公众号套话，能删就删，用自己的话收尾 |

### 句式层面的AI腔（靠语感判断，脚本扫不出来）
- 连续三段都以"这"开头 → 换主语。
- 每段都是"总—分—总" → 砍掉一半的总结句。
- 过度对称（"A是……，B也是……；A有……，B也有……"）→ 打破对称。
- 空洞升华（"在这个时代，我们每个人都……"）→ 落到具体的人。
- 正确的废话（"这背后的原因是复杂的"）→ 直接写原因到底是什么。
- 排比和成语堆砌、"不仅……更……"句式连发 → 拆掉几句，说大白话。

### 自检三问
每写完一章问自己：
1. 这段话里有没有一个具体的人、数字或场景？没有就加。
2. 这段话能不能发在朋友圈而不显得像通稿？不能就改。
3. 把"我"换成"笔者/本文"还通顺吗？如果通顺，说明第一人称是假的，要改出真"我"。

## 四、长文节奏

- 每800–1500字插入一个"呼吸点"：一个小故事、一段引语、一张配图、一个视觉组件、一个反问。宁可密一点，不要让读者连续三屏只看到纯文字。
- 每章结尾留一个钩子，引向下一章（"可真正让我意外的，是后面发生的事"）。
- 重分析章节之后跟一个故事章节，重故事章节之后跟一个分析章节，避免读者疲劳。
- 数据密集段落之后，用一句大白话翻译给读者听（"说人话就是……"）。
- **视觉节奏交替原则**：配图和组件不要扎堆也不要长期缺席。理想节奏是"段落→段落→组件/配图→段落→段落→组件/配图"，每3段左右必有一个视觉元素。相邻两个视觉元素尽量不同类型（刚用完数据卡就别再用数据卡，换金句卡或配图）。
- **色彩节奏**：三列数据卡用蓝/绿/橙三色、标签云五色轮换、时间线节点也可换色——让版面每隔一段就出现一块"颜色"，而不是从头到尾只有一种主色。
- **正文行内色彩**：比组件更密的色彩在正文里。每段至少一处荧光笔/彩色加粗/彩色数字，荧光笔五色按语义轮换（黄=观点、粉=细节、蓝=数据、绿=积极、橙=转折），让读者视线在段落中能抓住三四个彩色落点，而不是面对一整坨黑字。具体手法见第七节"正文内联色彩手法详解"。

## 五、配图与图注

### 配图密度
- 全文≥10张图，每800–1800字一张，每章至少1张，重磅章节2–3张。
- 配图类型要交替：封面图、场景插画、概念氛围图、信息图、人物故事图轮换，避免连续两张同风格同色调。

### 配图色彩要求（重要）
- AI 生图 prompt 中**必须强调色彩**：写明"色彩鲜艳明快、高饱和度、光影层次丰富、画面饱满有质感"，根据主题指定色调（如暖橙烟火气、冷蓝科技感、翠绿自然感）。
- 禁止生成灰暗、单调、素白、低饱和度的配图——长文里一张灰蒙蒙的图会让读者直接划走。
- 不同章节的配图在色调上有意识地变化：讲危机用偏冷暗色调，讲希望用暖亮色调，用色彩配合叙事情绪。
- **信息图/概念图要多彩**：发展历程、关系网络、结构拆解等内容，优先用 `image_gen` 生成色彩丰富的信息图（多色节点、多色连线、多色块对比），一张多彩信息图本身就是强视觉停顿，比纯文字+HTML组件更醒目。全文至少安排1–2张这类多彩信息图。

### 两种图注样式交替使用
1. **标准图注**：图片下方灰色小字居中，适合大多数配图。
2. **色条图注**：图注白字放在主题色色条上、与图片底部圆角衔接，杂志感更强，适合章节头图、重点配图。两种样式穿插使用，不要全文只用一种。

### 图注写法
- 图注不是图片说明，是正文的延伸。用一句话补充信息、制造悬念或表达态度。
- 图注示例（好）："这家开在巷子里的小店，菜单已经换了三回。"
- 图注示例（差）："图为某店铺照片。"
- 图注里不能出现"本文由AI生成"等身份声明；网络搜图统一写"图源：某某平台"。

## 六、事实底线

- 所有数字、日期、人名、机构名必须来自第1步采集的真实素材，不得编造。
- 不同来源说法冲突时，写"关于这件事有两种说法"并都列出，不要只取一个。
- 预测性判断要标明是作者判断还是某某机构的预测。
- 宁可某一章短一些，也不要用水和编造填充字数。

## 七、视觉组件使用

模板提供以下22类组件，直接复制对应 HTML 片段改文字即可。**不要自行发明新样式**，保持全文统一。

### 纸质背景与字色（不要改）
- 正文容器固定为暖米色 `#faf7f0`，像米色纸张，不随主题色变化，不要改成纯白。
- 正文用柔灰色 `#3a3a3a` 而非纯黑，降低对比度，长读不刺眼；标题仍用近黑 `#1a1a1` 保持层次。
- 组件卡片用纯白 `#ffffff` 浮在暖米底上，形成"白纸卡片落在米色桌面"的层次感。
- 换主题只换强调色（章节色条、渐变标题、数据卡色等），纸色和字色不动。

### 正文内联色彩手法详解（防止满屏黑字疲劳）

每个正文段落至少使用以下一种手法，让读者每隔一两行就能看到一个"颜色落点"。手法可以组合使用，但同一段内不要超过3处彩色，否则杂乱。

**① 主题色加粗——标关键词**
```html
<span style="color:#2d5f4f;font-weight:700;">关键词</span>
```
标段落中最重要的1–2个名词或判断。随主题色变化，是全文的"主线颜色"。

**② 多色荧光笔——按语义选色（最常用，每段必用）**
| 颜色 | 底色 | 语义 | 适用内容 |
|---|---|---|---|
| 黄 | `#fef9c3` | 核心观点 | 作者最想让读者记住的判断、结论 |
| 粉 | `#fce7f3` | 反常识/有趣细节 | 让人意外的事实、戏剧性细节 |
| 蓝 | `#dbeafe` | 数据/数字 | 数字、比例、统计相关的短语 |
| 绿 | `#d1fae5` | 积极/增长 | 好消息、增长、支持方 |
| 橙 | `#fed7aa` | 转折/注意 | 转折词、需要留意的风险 |
| 主题色 | `#dcebe5` | 主题强调 | 和主色呼应的关键概念 |

写法：`<span style="background:#fef9c3;padding:0 4px;border-radius:3px;">要标亮的文字</span>`
**五色要轮换**，不要一整章全用黄色荧光笔，也不要连续两句都标亮。

**③ 关键数字彩色大号——砸重点**
```html
<span style="color:#d4564b;font-weight:800;font-size:19px;">38块</span>
```
- 红色 `#d4564b`：价格高、下降、亏损、警示数字
- 绿色 `#3a9d6d`：增长、利好、积极数字
- 主题色：特别重要但无正负倾向的数字
正文中出现的关键数据，优先用这种方式突出，而不是让它淹没在黑字里。

**④ 段首彩色引导词——带节奏**
```html
<span style="color:#2d5f4f;font-weight:800;font-size:18px;">先说结论。</span>后面接正文……
```
用2–4个字的彩色加粗放大开场，如"先说结论。""问题在于。""有意思的是。""说白了。""可你猜怎么着。""更狠的是。"让读者一眼知道这段要讲什么。每章用3–5次，不要每段都用。

**⑤ 核心句整句强调——单独成段**
```html
<p style="margin:0 0 20px;font-size:18px;color:#2d5f4f;font-weight:700;line-height:1.9;">这一句是全段核心判断，主题色加粗放大单独成段。</p>
```
每章1–3次，放在段落开头或结尾，像"路标"一样指引读者。不要滥用，多了就没有重点。

**⑥ 情绪/判断词着色——带体温**
```html
这事儿让人<span style="color:#d4564b;font-weight:700;">愤怒</span>，更多的是<span style="color:#d9832e;font-weight:700;">无奈</span>。
```
红=愤怒/警示，橙=惋惜/无奈，蓝=冷静/理性，绿=赞许。让作者的情绪通过颜色直接传达，而不是靠形容词堆砌。

### 使用原则
- **组件为内容服务**，不是每段都要套组件。连续3段纯文字时，必须用一个组件或配图打破节奏。
- **类型要交替**：刚用完数据卡就换金句卡或配图，不要连续用同一种组件。相邻两个视觉元素的颜色和形态尽量不同。
- **色彩要丰富但不混乱**：主色（随主题）管结构（章节标题、小节色块、渐变标题），五个功能色（蓝绿橙红紫）管内容标签和数据卡，金色管金句和导语，荧光笔五色管正文行内强调。不要给整段正文加背景色。
- 彩色标签段落的五色对应不同语气（蓝=冷静/背景、绿=积极/增长、橙=转折/注意、红=风险/反方、紫=延伸/冷知识），但**标签词不要固定写"定义/解析/影响/警示"**，要根据段落内容自定义2–4字的短词，如"算账""翻车""别急""冷知识""划重点""反直觉"，让标签本身也有信息量和个性。不要每段都加标签，否则像PPT。
- 三列数据卡只放最有冲击力的3个数字，数字必须有来源；单数据大卡留给全文最核心的一个数字。
- 时间线节点控制在3–6个，每个节点一句话说清发生了什么；节点颜色可按时间阶段情绪切换（早期蓝=萌芽、中期橙=火热、后期红=退潮）。
- 胶囊标签里放年份、章节序号或关键词，不要放长句。
- 渐变章节标题比浅底卡片更"重"，适合每章开头或全文最关键的2–5个章节，不要每章都用渐变，否则没有层次。
- 对话气泡比金句卡片更口语化、更轻，适合放评论区原话、采访中的短句；金句卡片适合放有分量的判断和点睛之笔。两者穿插使用。
- 双列对比卡的两列颜色要有对比关系（蓝vs红=对立、蓝vs绿=演进、橙vs紫=反差），不要用相近色。
- Q&A块适合在读者最可能产生疑问的地方出现，问题要真实（来自评论区或采访），回答要直给不绕弯。
- 红绿对比行和双列对比卡功能相似但更轻量：对比内容只有一两句话用对比行，需要展开论述用双列卡。

## 八、配色选择

默认竹青配色适合大多数深度文。定稿后根据主题运行 `python3 scripts/apply_theme.py article.html <主题>` 一键换色，**不要手动改颜色**。

| 主题 | 适用内容 |
|---|---|
| bamboo（竹青，默认） | 文学、人物、深度调查、社会观察——拿不准就用它 |
| tech-blue（科技蓝） | 科技、互联网、AI、数码、商业分析 |
| warm-orange（暖橙） | 美食、消费、市井生活、烟火气、亲子 |
| forest（森林绿） | 自然、环保、健康、农业、户外 |
| elegant-purple（典雅紫） | 文化、艺术、教育、女性议题、书评 |
| china-red（中国红） | 时政、宏大叙事、节庆、历史、体育赛事 |
| ink-dark（墨黑） | 严肃评论、财经、法律、案件复盘 |
| sunset（日落橘） | 人物故事、情感、返乡、怀旧 |
| teal（青蓝） | 科普、新知、医学、商业新知 |
| rose（玫红） | 时尚、娱乐、情感、年轻向话题 |

蓝/绿/橙/红/紫五个功能标签色是固定的，不随主题变化，用于"定义/解析/影响/警示/延伸"的语义区分。金色（#c9b879）用于金句卡片和导语，也是固定装饰色。

每个主题色包含主色、深色（用于渐变标题和单数据大卡）、浅底、高亮底、柔和底五个色阶，由 `apply_theme.py` 一键切换，无需手动改色。
